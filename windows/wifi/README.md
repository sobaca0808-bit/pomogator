# ПОМОГАТОР Wi-Fi v0.2.4

Утилита для Windows 10 x64 управляет Hosted Network и проверяет общий доступ к интернету (ICS). Поддержка Hosted Network зависит от Wi-Fi-адаптера, драйвера и политики Windows. На современных драйверах может быть доступен только «Мобильный хот-спот» Windows.

## Запуск

1. Скачайте архив `PomogatorWifi-0.2.4-win-x64` в разделе **Artifacts** проверки Windows на GitHub и распакуйте его в постоянную папку. Внутри `PomogatorWifi.exe`, инструкция и контрольная сумма. Нужен .NET Framework 4.8, который входит в Windows 10 22H2. Если сеанс удерживает прежняя версия, завершите его старой копией приложения в удобное время.
2. Подключите USB Wi-Fi-адаптер, запустите существующее PPPoE-подключение и откройте EXE обычным способом.
3. В разделе **Настроить сеть** укажите имя не длиннее 32 байт UTF-8 и пароль от 8 до 63 печатных символов ASCII. Приложение хранит настройки через Windows DPAPI для текущей учётной записи. Если точка уже работает, новое имя и пароль применятся при следующем запуске точки.
4. Нажмите кнопку питания. Для Wi-Fi нужна поддержка Hosted Network. Программа сначала запускает точку, поскольку её виртуальный адаптер может появиться только после запуска. Затем она показывает имена PPPoE и виртуального адаптера и спрашивает, разрешено ли изменить ICS. Согласитесь, если оба подключения нужные. Windows может запросить повышение прав. Для восстановления используются те же настройки и учётная запись Windows.
5. Дождитесь статуса **Подтверждён Windows** в строке ICS. Он означает, что Windows вернула ожидаемые роли общего доступа. Проверку интернета на телефоне выполните в браузере телефона с выключенными мобильными данными. Поле **Интернет на ПК** показывает доступность HTTPS с компьютера через текущие маршруты Windows. На него может влиять активный VPN.
6. Чтобы остановить собственную точку, нажмите кнопку питания или выберите команду в трее. Если ПОМОГАТОР менял ICS, он попросит вернуть исходные роли. Если Windows не подтверждает их восстановление, утилита предложит оставить текущие настройки ICS и завершить только собственный сеанс Wi-Fi.

### Уже работает другая точка

Экран показывает внешний Hosted Network либо обнаруженный мобильный хот-спот / Wi-Fi Direct. Windows сообщает механизм и состояние, а идентификатор процесса, запустившего чужую Hosted Network, недоступен. Для диагностики можно оставить раздачу включённой. Если Windows показывает работающую точку, а приложение временно не получает ответ своего помощника, экран показывает **Уточняем управление Wi-Fi**. Кнопка снова станет доступна, когда помощник подтвердит собственный сеанс. Пока внешняя точка активна, можно открывать настройки, просматривать и экспортировать диагностику.

Закрытие окна и команда **Выход** в трее оставляют сетевой сеанс приложения в отдельном помощнике до явного выключения точки или завершения сеанса Windows. Открытие той же копии EXE снова подключает окно к помощнику. Установите обновление перед следующим плановым запуском точки. Активный сеанс прежней сборки и чужие точки остаются у своего владельца. Новый EXE не присваивает их по совпадающему имени сети.

В v0.2.2 подтверждённую Hosted Network можно отключить вручную кнопкой питания или командой **Отключить раздачу** в трее. Для внешней точки сверьте её имя, адаптер и BSSID в диалоге, подтвердите отключение и при необходимости запрос UAC. Если с момента проверки изменился сеанс или адаптер, операция отменяется. Утилита проверяет итог по WLAN. Этот способ действует только для Hosted Network.

## Автоматизация

Все настройки изначально выключены и работают независимо.

| Настройка | Действие |
| --- | --- |
| Запускать вместе с Windows | Запускает окно при входе в текущую учётную запись. |
| Автоматически включать Wi-Fi | При открытии запускает свободную Hosted Network с сохранёнными параметрами. Для первой настройки ICS используйте явное подтверждение в диагностике. |
| Сворачивать в системный трей | Крестик скрывает окно и сохраняет мониторинг. Меню трея показывает состояние и доступное управление. |
| Восстанавливать раздачу | Пока приложение открыто или в трее, отслеживает отключение PPPoE или потерю ранее подтверждённого HTTPS. После возврата делает одну попытку для своего сеанса. После выхода из сна в течение 45 секунд действует то же правило, если Windows подтвердила состояние точки и PPPoE вернулся. Изменяет только ранее одобренную пару ICS после повторной проверки, с запросом UAC при необходимости. |

Для ручной настройки уже запущенной своей точки откройте **Диагностика → Настроить общий доступ**. Если изменились подключения или другая программа установила свои роли ICS, кнопка становится недоступной до повторной проверки. Сеанс приложения нельзя безопасно восстановить после завершения Windows по старым идентификаторам. Новая настройка после перезагрузки требует повторной проверки и подтверждения.

## Диагностика

Окно показывает состояние WLAN, PPPoE, ICS, внешнего хот-спота и пробного HTTPS. У некоторых драйверов Windows не сообщает состояние мобильного хот-спота или число его клиентов. Для Hosted Network число берётся из списка подключённых устройств Windows.

При потере собственного сеанса утилита повторно читает состояние WLAN через отдельный клиент. Когда Windows подтверждает, что точка выключена и доступна для запуска, попытка восстановления использует новый подписанный на события дескриптор WLAN. После отказа старта действует короткая пауза. Автовосстановление зависит от включённой настройки и прежних условий, включая подтверждение источника интернета. Состояния WlanSvc и SharedAccess читаются для диагностики. Запуск и перезапуск служб осуществляются пользователем средствами Windows.

Код `5023` указывает на неподходящее состояние для текущей операции. При `1062` проверьте, запущена ли «Автонастройка WLAN». `31` с причиной `19` означает, что Windows сообщила об отказе запуска виртуальной точки. Проверьте поддержку Hosted Network и состояние адаптера. Эти команды только читают сведения:

```powershell
Get-Service WlanSvc,SharedAccess
netsh wlan show drivers
netsh wlan show hostednetwork
```

ICS проверяется отдельно с ограничением ожидания. `SharingInstalled=false` означает, что COM вернул признак недоступности, а запись `HRESULT=…` содержит код ошибки Windows COM. Если чтение неполное или не завершилось вовремя, изменение общего доступа недоступно.

Если `INetSharingConfigurationForINetConnection` возвращает `0x80004002` на отключённом объекте без сетевого носителя и признаков ICS, проверка остальных объектов продолжается. Журнал сохраняет номер объекта, GUID, MediaType, Status и HRESULT. Ошибка на адаптере, который может влиять на раздачу, блокирует запись ICS, даже если Hosted Network доступна.

Файл журнала находится в `%LOCALAPPDATA%\PomogatorWifi\diagnostic-v2.log`. Экспорт TXT содержит результаты и технические коды. Пароль, имя Wi-Fi и данные PPPoE в журнал не записываются. Отчёт может содержать сетевые идентификаторы, поэтому перед отправкой его стоит просмотреть.

### Точка запущена, клиент не подключается

1. Оставьте точку под тем же управлением, при котором воспроизводится сбой. Для внешней Hosted Network откройте **Диагностика** и нажмите **Записать попытку · 30 с**. Начните одно подключение с телефона сразу после приглашения. Запишите сообщение телефона. Если есть второй клиент, проведите отдельную попытку и сохраните отдельный TXT.
2. Сравните состояния точки, радио и станции. При нуле клиентов Windows могла отклонить соединение ещё до появления события об аутентификации. Причину без дополнительных данных установить нельзя. Проверьте соответствие пароля способу запуска. ПОМОГАТОР задаёт непостоянный вторичный ключ для своего сеанса. При последующем запуске через `netsh` Windows может использовать другой ключ. Вводите известный пароль только в форме настройки или на телефоне.
3. После подтверждения аутентификации посмотрите полученный IPv4 в сведениях о Wi-Fi на телефоне. Адрес `169.254.x.x` указывает на локальную автонастройку. Состояние таблицы соседей Windows даёт дополнительный признак связи, способ выдачи адреса из него не определяется.
4. При подтверждённых WPA2 и IPv4 проверьте интернет на телефоне с отключёнными мобильными данными. На этом этапе сравните проверку ICS и доступность интернета на ПК.

Запись добавляет уведомления Hosted Network о состоянии точки, радио и станциях, сведения о виртуальном адаптере, идентификаторы событий WLAN AutoConfig и предупреждения либо ошибки известных драйверов, NDIS и USB. Журнал Windows может содержать события других интерфейсов. Запись извлекает только время, поставщика, ID и уровень события. Пароли, ключи, MAC- и IP-адреса клиентов в запись попытки не входят. Программа выполняет чтение и оставляет восстановление адаптера и проверку ключа пользователю.

В v0.2.1 обновление экрана только читает состояние. Команда **Выключить Wi-Fi** подтверждается по идентификатору сеанса и GUID адаптера и освобождает только ссылку ПОМОГАТОРА через `WlanHostedNetworkStopUsing`. Если после этого Windows ещё показывает активную точку, её может удерживать другой клиент или Windows. ПОМОГАТОР оставляет её работающей. Журнал `hosted_released` содержит источник явной команды (`window` или `tray`), результат Windows и состояние Hosted Network. Отдельно отмечаются потери подтверждения и прерывания сеанса, о которых сообщает WLAN.

## Сборка и проверка

Запустите из корня репозитория с .NET 8 SDK:

```powershell
dotnet run --project windows/wifi/tests/PolicyTests.csproj -c Release
dotnet build windows/wifi/PomogatorWifi.csproj -c Release
dotnet build windows/wifi/tests/ui/WifiUiTests.csproj -c Release
& windows/wifi/tests/ui/bin/Release/net48/WifiUiTests.exe screenshots
```

Сборка появится в `windows/wifi/bin/Release/net48/PomogatorWifi.exe`. Windows CI проверяет WinForms, DPAPI, трей, отдельное тестовое значение автозапуска и реальный именованный канал Windows с имитацией адаптера. Сценарий запускает сеанс, закрывает окно, выдерживает 61 секунду без запросов, открывает окно снова и подтверждает OFF после обновления статуса. Превью окон содержат демонстрационные данные. Масштабы 125% и 150% в CI имитируются изменением размеров WinForms. Проверка реального DPI и взаимодействия драйвера с системой проводится отдельно.

### Проверка на Windows 10 с Ralink и PPPoE

- Если сейчас раздача работает, оставьте её включённой. Зафиксируйте состояние в новом окне и при необходимости экспортируйте журнал.
- При следующем плановом запуске собственной точки засеките больше минуты, затем обновите диагностику и проверьте, что кнопка выключения доступна. Сверните окно в трей и откройте его снова. Когда закончите работу с точкой, нажмите обычную кнопку выключения. В журнале сравните `hosted_started`, `hosted_ownership_confirmed` и `hosted_released`; последний укажет источник команды и ответ WLAN.
- Проверьте повторный запуск после отключения. Если точка пропадёт сама, откройте диагностику и сделайте одну попытку восстановления только после появления доступной Hosted Network. В журнале проверьте `hosted_client_reopened`, код операции WLAN и фактическое состояние точки.
- Проверьте PPPoE, согласование ICS, подключение телефона, число клиентов и пробуждение из сна с включённым восстановлением. Если Windows оставит активную точку после освобождения сеанса, сохраните отчёт с её состоянием.
- Проверьте с активными UBoost и Kaspersky, что настройки и подключения этих программ сохраняются. В изолированном сценарии проверьте потерю и восстановление PPPoE, штатное отключение и возврат ролей ICS.
- Проверьте Windows-автозапуск отдельно от автоматического включения Wi-Fi, трей и вид окон при системных 100%, 125% и 150%.
