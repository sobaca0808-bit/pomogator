# ПОМОГАТОР VPN v0.2.0

Русскоязычное WPF-приложение для Windows 10 x64. В комплект входят .NET и Xray-core 26.11.9. Учётная запись и права администратора не требуются. [Исходники Xray-core и лицензия MPL 2.0](https://github.com/XTLS/Xray-core/tree/v26.11.9)

## Запуск

1. Распакуйте артефакт `PomogatorVpn-0.2.0-win-x64` успешного запуска GitHub Actions. Запустите `PomogatorVpn.exe` из этой папки.
2. Вставьте ссылку VLESS, откройте файл или добавьте подписку HTTPS. Выберите сервер в списке и нажмите круглую кнопку.
3. После статуса **Подключён и проверен** в карточке появятся локальный адрес и время сеанса. По умолчанию приложение запускает HTTP-прокси на `127.0.0.1`. В полном профиле также может быть локальный SOCKS.
4. Через **Настройки** можно выбрать системный прокси Windows. Приложение применит его только после явного подтверждения и успешной проверки VLESS.
5. Сворачивание оставляет сеанс в трее. Значок и подпись отражают состояние. Меню трея позволяет открыть окно, отключиться и выйти. Крестик и команда **Выход** завершают сеанс.

Состояния в окне и трее: серый **Отключён**, жёлтый **Подключается**, зелёный **Подключён и проверен**, красный **Ошибка подключения**, голубой **Отключается**. Анимация ожидания учитывает системную настройку анимаций. В настройках можно включить запуск приложения в трее вместе с Windows. По умолчанию автозапуск выключен. Приложение после автозапуска ждёт выбора пользователя и не подключает VPN само.

## Импорт EasyGoVPN и Xray

При открытии клиентского JSON выберите режим явно:

- **Полный профиль** сохраняет совместимые DNS, порядок и правила маршрутизации, теги и исходящие подключения VLESS, Freedom (`direct`), Blackhole (`block`) и DNS. Входы HTTP и SOCKS создаются заново на свободных портах loopback с исходными тегами и совместимыми настройками распознавания протоколов. Входы с учётными данными, балансировщики, внешние файлы правил и произвольные исходящие протоколы не поддерживаются. Обычные запросы могут идти напрямую, если такое правило было в полном профиле.
- **Упрощённый профиль** переносит первый VLESS-сервер и его параметры. Маршрутизация, DNS и остальные исходящие подключения из файла опускаются. Если полный профиль несовместим, приложение сообщит об ошибке. Упрощённый вариант можно выбрать при повторном импорте.

Поддерживаются TLS, REALITY, SNI, fingerprint, Vision для TCP, TCP, WebSocket, gRPC, HTTPUpgrade и XHTTP. REALITY работает с TCP, XHTTP и gRPC. Импорт TCP + REALITY поддерживает `serverName`, `publicKey` (или `password` в новой схеме Xray), `shortId`, UUID и `flow`. Профили без TLS или REALITY предназначены только для loopback-тестов.

Подписки читаются напрямую с указанного HTTPS-адреса. Поддерживаются списки VLESS в UTF‑8 или Base64 и клиентский JSON. Допускаются до трёх перенаправлений HTTPS на том же хосте и порту, включая относительные. Другой хост, смена протокола и цепочки с циклом отклоняются. Ответы 401, 403, 404, 410, 429 и другие HTTP-ошибки выводятся с указанием кода. Лимит загрузки 1 МБ, лимит списка 100 профилей.

## Диагностика

**Проверить соединение** открывает панель с отдельными результатами Xray, локального прокси, контрольного HTTPS и WinINet. **Измерить задержку** замеряет время установления TCP-соединения с сервером, включая разрешение имени при необходимости. Это не ICMP и не задержка до сайта через VPN.

Зелёный статус появляется после запуска Xray, проверки принадлежности локальных портов этому процессу и получения HTTP 204 от `https://www.gstatic.com/generate_204` с проверкой сертификата. В полном профиле HTTPS-проба идёт в отдельный loopback-вход с первым правилом на выбранный VLESS. Это проверяет выбранный выход даже при наличии правил для прямого трафика. Проверка не измеряет публичный IP и не подтверждает маршрут каждого сайта.

Проверка выполняется каждые 30 секунд, пока сеанс активен. При выходе Xray или провале проверки приложение показывает причину, завершает сеанс и пытается восстановить исходный системный прокси. Повторное подключение запускается пользователем. Журнал и TXT-экспорт содержат результаты и коды ошибок. Ссылки подписок, ключи, UUID и вывод ядра в них не попадают.

## Настройки Windows и восстановление

Меняются только запрошенные параметры WinINet для LAN текущего пользователя и, при включении автозапуска, запись ПОМОГАТОР VPN в HKCU. Некоторые приложения и настройки PPPoE могут использовать отдельный прокси. TUN, DNS Windows, сетевые маршруты, Wi-Fi, раздача, Kaspersky и UBoost находятся вне управления приложения.

Исходное состояние WinINet сохраняется с DPAPI до изменения. Приложение отклоняет включение, если уже назначен ручной прокси или PAC. Восстановление выполняется только пока текущие параметры совпадают с применёнными. При изменении извне остаётся локальный режим. После аварийного выхода следующий запуск предлагает восстановление с той же проверкой. Job Object Windows завершает дочерний Xray при завершении приложения. Профили шифруются DPAPI в `%LOCALAPPDATA%\PomogatorVpn` и передаются ядру через stdin.

## Сборка и проверки

Из корня репозитория, с .NET SDK 8:

```powershell
dotnet run --project windows/vpn/tests/Tests.csproj -c Release
dotnet publish windows/vpn/app/PomogatorVpn.csproj -c Release -r win-x64 --self-contained true -o windows/vpn/dist
./windows/vpn/scripts/Get-Xray.ps1 -Destination windows/vpn/dist
```

Для интеграционного теста задайте `POMOGATOR_TEST_XRAY` абсолютным путём к Xray из комплекта. Тест использует только синтетические данные и loopback. Проверку реального WinINet через `POMOGATOR_TEST_WININET=1` запускайте только на изолированном Windows-раннере без действующего прокси. Отдельный WPF-тест в CI проверяет пять состояний и трей и сохраняет PNG при рендеринге 100%, 125% и 150%.

На целевом ПК отдельно проверьте реальный профиль EasyGoVPN, совместимость с вашим сервером и другими клиентами, отображение при системном масштабировании Windows и восстановление при аварийном завершении. CI визуализирует окно в указанном DPI, а переключение масштаба реального дисплея и поведение браузеров с PPPoE проверяются на месте.
