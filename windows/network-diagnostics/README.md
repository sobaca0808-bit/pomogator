# ПОМОГАТОР — Диагностика сети v0.1

Утилита для Windows 10 в режиме чтения. Требуются .NET Framework 4.8 и штатный Windows PowerShell 5.1. Устанавливать приложение или Python не нужно.

## Запуск

1. Запустите `release/PomogatorNetworkDiagnostics.exe`. Оставьте PPPoE, Ralink и VPN в том состоянии, в котором проявляется симптом.
2. Нажмите **Полная диагностика**. Проверки выполняются независимо, каждая ограничена по времени. Результаты появляются по мере выполнения, подробный отчёт выводится после завершения.
3. Нажмите **Сохранить отчёт**, прочитайте предупреждение и выберите TXT или JSON. В отчёте есть время с часовым поясом, длительность проверок, статусы, пояснения и коды ошибок.
4. Служебный журнал доступен из окна и хранится в `%LOCALAPPDATA%\PomogatorNetworkDiagnostics\diagnostic.log`. В нём остаются время, идентификаторы проверок, статусы, длительность и коды. Адреса, имена адаптеров и пути экспорта в журнал не пишутся.

По умолчанию утилита запускается с правами текущего пользователя. Если Windows отказала в чтении нужного журнала, можно повторить диагностику от имени администратора. Приложение читает настройки, отправляет контрольные сетевые запросы и пишет локальный журнал и выбранный файл отчёта. Оно не меняет сетевую конфигурацию, подключения, службы или настройки ICS и Hosted Network.

Перед отправкой отчёта проверьте его содержимое. В нём могут быть локальные и публичные IP-адреса, DNS-серверы, маршруты, имена адаптеров и GUID. Утилита не собирает пароли, PPPoE-учётные данные, ключи VPN, полные тексты событий, URL PAC и учётные данные прокси.

## Что проверить на Windows 10

- В отчёте найдите Ralink и виртуальные адаптеры, состояние драйверов, активный PPPoE по данным RAS, текущие DNS и маршруты. Состояние «Неопознанная сеть» и запуск SharedAccess вручную сами по себе не означают неисправность.
- В блоке ICS найдите `INetSharingConfigurationForINetConnection #…`. Если вернётся `0x80004002`, сопоставьте номер с типом, GUID и состоянием подключения в этом же отчёте. Номер может отличаться от `#4`: он зависит от порядка перечисления Windows. Чтение остальных подключений продолжается.
- Сопоставьте блоки TCP по IP, системного DNS и сайтов. Для TCP используются IPv4-адреса `1.1.1.1:443` и `8.8.8.8:443`. Для DNS и HTTP(S) проверяются `www.msftconnecttest.com` и `www.microsoft.com`. Прямой запрос не использует системный прокси, но идёт по действующему маршруту Windows и может проходить через VPN. Проксированный запрос выполняется, только если Windows выбрала прокси для данного URL. Утилита не меняет маршрут и не передаёт прокси учётные данные.
- Если браузер показывает чёрный экран при успешных контрольных запросах, зафиксируйте время и сопоставьте его с событиями Windows. Сетевой отчёт не проверяет отрисовку, расширения, браузерный VPN и доступность конкретного проблемного сайта.
- Проверьте сохранение TXT и JSON и сравните результаты. Если часть журналов не читается с обычными правами, это должно быть отражено как неполная диагностика.

## Сборка и тесты

Из корня репозитория с .NET SDK 8:

```powershell
dotnet build windows/network-diagnostics/PomogatorNetworkDiagnostics.csproj -c Release
dotnet run --project windows/network-diagnostics/tests/DiagnosticsTests.csproj -c Release
powershell -NoProfile -File windows/network-diagnostics/tests/ProbeScripts.Tests.ps1
```

Собранный EXE расположен в `bin/Release/net48`. Автоматические тесты проверяют обработку кодов, продолжение диагностики после сбоя одного объекта ICS, разбор и сериализацию отчёта, очистку адреса прокси, тайм-аут процессов, синтаксис и результаты PowerShell на тестовых данных. Работа Windows API с реальными драйверами, службами, журналами, VPN и PPPoE проверяется на целевом компьютере.
